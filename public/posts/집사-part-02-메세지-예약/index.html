집사 - PART 02. 메세지 예약

Project DIA(Do It, AI) #4

August 11, 2026

디스코드 음성 회의 기록 및 요약 봇 **집사(defib-secretary)**에 회의 흐름과 완전히 독립적으로 동작하는 메시지 예약 발송 시스템을 추가했다. 특정 시각에 지정된 채널로 메시지를 자동 전송하는 기능이다.

이 글에서는 디스코드 API가 가진 한계를 극복하며 예약 스케줄러, 대화형 컴포넌트, 입력값 처리 등을 어떻게 설계하고 코드로 구현했는지 다룬다.

시스템 아키텍처 및 핵심 파일

예약 시스템은 기존의 음성 녹음 파이프라인과 겹치지 않도록 모듈화하여 설계했다.

  • src/reservation.service.js: 예약 데이터 CRUD, tmp/reservations.json 파일 기반 영속화, 15초 주기 폴링 스케줄러, 시간 선택 피커용 임시 drafts 상태 관리.
  • src/ui.js: 예약 목록 임베드 메시지, 예약 취소용 콤보박스, 날짜/시/분 피커 컴포넌트 빌더.
  • index.js: 슬래시 커맨드 등록 및 이벤트 라우팅(버튼 클릭, 셀렉트 메뉴 선택, 커맨드 핸들러).

슬래시 커맨드 설계와 API 제약 사항

디스코드 슬래시 커맨드를 구현하는 과정에서 몇 가지 API 수준의 제약이 있었다.

1. 옵션 순서 및 서브커맨드 제약

Discord API는 필수 옵션(Required)이 선택 옵션(Optional)보다 무조건 앞에 위치하도록 강제한다. SlashCommandBuilder에서 이 규칙을 위반하면 런타임에 즉시 예외(throw)를 발생시킨다.

원래는 사용자가 직관적으로 인식할 수 있는 [날짜] -> [시간] -> [메시지] 순서로 입력을 받으려 했으나, 메시지만 필수 값이었기 때문에 다음과 같이 순서를 재배치했다.

// `/예약 등록` 커맨드 구조
/예약 등록 [메시지:필수] [시간:선택] [날짜:선택] [채널:선택]

또한, 디스코드 API 상 최상위 옵션과 서브커맨드를 한 커맨드 안에 동시에 둘 수 없다. 이에 따라 취소와 수정 기능은 서브커맨드로 분리했다.

  • /예약 등록
  • /예약 취소
  • /예약 수정

2. 채널 포지션 및 메시지 길이 한도

  • 채널 선택: 디스코드 네이티브 채널 타입을 옵션으로 지정하여 해결했다. 생략할 경우 .env에 정의된 RESERVATION_DEFAULT_CHANNEL_ID를 바라보고, 이마저 없으면 명령어를 실행한 현재 채널을 기본값으로 사용한다.
  • 메시지 길이 제한: 예약 메시지 본문은 최대 200자(setMaxLength(200))로 하드 리밋을 걸었다. 무제한 입력을 허용하면 전체 예약 목록을 조회할 때 디스코드 임베드 제한 글자 수(4096자)를 초과해 에러가 발생할 수 있기 때문이다.

메모리 기반 대화형 시간 선택 피커

사용자가 시간을 타이핑하는 번거로움을 줄이기 위해 “클릭으로 예약 시각을 고르는 기능"을 설계했다. 그러나 디스코드 API는 달력이나 시간 선택 전용 UI 컴포넌트를 지원하지 않는다.

이를 우회하기 위해 /예약 등록 시 시간 옵션을 생략하면 아래와 같은 대화형 UI 피커를 동적으로 렌더링하도록 구현했다.

  1. 컴포넌트 구성: 날짜(향후 14일치), 시(24시간), 분(10분 단위 6개)을 선택할 수 있는 3개의 셀렉트 메뉴와 최종 확인 버튼 배치.
  2. drafts 임시 세션 관리: 사용자가 최종 확인을 누르기 전까지 선택한 값들을 임시 저장해야 한다. 이를 DB에 매번 저장하는 것은 낭비이므로, 서버 메모리 상의 drafts Map 객체에 draftId를 키로 하여 임시 상태를 들고 있게 했다.
  3. customId를 통한 상태 연결: 디스코드 UI 컴포넌트의 customId에 draftId를 인코딩하여 넘김으로써, 사용자가 조작하는 피커와 메모리의 drafts 상태를 매핑했다.
  4. 만료 처리: 임시 피커를 띄운 지 10분이 지나도 최종 확인을 누르지 않으면 해당 draft는 메모리에서 자동으로 지워진다.

15초 주기 폴링 스케줄러

예약을 실제 정해진 시간에 발송하는 로직은 Node.js의 setTimeout 대신 15초 주기의 폴링(Polling) 방식을 채택했다.

  • 이유: setTimeout은 최대 지연 시간 제한(약 24.8일)이 존재하여 먼 미래의 예약을 처리하기 어렵다. 또한 호스트 노트북 lid-switch 오작동, 컨테이너 재배포 등으로 프로세스가 재시작될 경우 타이머가 전부 깨지게 된다.
  • 구현 방식: 15초마다 한 번씩 tmp/reservations.json에 영속화된 예약 목록을 스캔한다. 현재 KST 시각 기준 마감 시각을 넘긴 예약이 존재하면 즉시 메시지를 발송하고 해당 항목을 파일에서 지운다.
  • 영속화: 예약 데이터는 JSON 파일 형태로 디스크에 안전하게 쓰여 있으므로, 봇이 재배포되거나 죽었다 살아나도 유실되지 않는다.

동적 번호 매김 시스템

사용자가 예약 목록을 조회했을 때 보여줄 예약 번호를 고유하고 고정된 ID 대신 동적 번호 체계로 설계했다.

  • 원리: 사용자가 목록 조회를 요청한 시점에 전체 예약을 발송 시각 오름차순으로 정렬한다. 그 후 정렬된 순서대로 01, 02와 같은 2자리 0패딩 번호를 부여하여 노출한다.
  • 장점: 디스크에 UUID 같은 지저분한 고유식별자를 복잡하게 관리할 필요가 없다. 사용자는 방금 자신이 화면에서 확인한 번호를 그대로 /예약 취소 번호:1과 같이 넘기기만 하면 되므로 직관적이다.
  • 트레이드오프: 목록을 확인한 시점과 실제로 취소 명령어를 입력하는 짧은 찰나에 다른 사용자가 예약을 추가하거나 삭제하면 인덱스가 한 칸씩 밀릴 수 있다. 다만 사내 소수 회의 환경에서는 동시 조작 빈도가 극히 낮아 이 방식을 고수했다.

예약 메시지 줄바꿈 문제 해결 (\n 치환)

슬래시 커맨드로 메시지를 예약할 때 사용자가 Enter를 치면 디스코드 클라이언트 내부 한계로 인해 개행 문자가 들어가지 않고 그대로 명령어가 전송되는 문제가 있었다.

이를 해결하기 위해 모달 입력창으로 인터페이스를 전면 개편하는 대신, 기존 슬래시 커맨드 흐름을 유지하며 입력값 포맷팅 필터를 거치도록 수정했다.

// 입력 필터 유틸리티 함수
function normalizeReservationMessage(message) {
  // 사용자가 입력한 리터럴 '\\n'을 실제 개행 문자로 치환
  return message.replace(/\\\\n/g, '\\n');
}

예약 등록(/예약 등록)과 예약 수정(/예약 수정) 비즈니스 로직에 이 normalizeReservationMessage 필터를 일괄 적용했다. 아울러 슬래시 커맨드의 도움말 설명 부분에 **(줄바꿈은 \\n 으로 입력)**이라는 문구를 추가하여 사용자가 쉽게 줄바꿈을 활용할 수 있도록 가이드했다.

테스트 및 안정성 검증

로컬 개발 환경의 한계(디스코드 봇 토큰 없음)로 인해 실제 디스코드 서버와의 E2E(End-to-End) 테스트는 수행할 수 없었다. 대신 단위 및 스모크 테스트를 최대한 촘촘하게 작성하여 품질을 검증했다.

  1. 문법 및 뼈대 검증: node --check를 이용해 문법 에러가 없는지 체크했다.
  2. 도커 컨테이너 격리 테스트: Docker 내 node:22-slim 이미지 위에서 @discordjs/opus 네이티브 빌드를 생략(--ignore-scripts 옵션 사용)한 채로 구동 환경을 구축했다.
  3. 핵심 기능 로직 테스트:
    • 예약 데이터의 생성, 수정, 삭제(CRUD) 및 JSON 파일 저장 흐름 검증
    • 정렬 상태에 따른 예약 동적 번호 재매김 결과 검증
    • 임시 피커용 drafts 상태 전환 흐름 검증
    • time.util.js를 사용한 KST ↔ UTC 시간 변환 정확성 검증
  4. 스키마 검증: SlashCommandBuilder를 거쳐 빌드된 최종 디스코드 커맨드 스키마가 예외 없이 올바른 JSON 규격(.toJSON())으로 변환되는지 최종 확인을 완료했다.
