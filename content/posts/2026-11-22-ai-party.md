> **요약**  
> 만든 것 · 여러 AI를 캐릭터 탭으로 나란히 띄워 함께 작업하는 Obsidian 플러그인  
> 핵심 판단 · AI마다 다른 파일 쓰기 방식 대신, 플러그인이 같은 권한 기준으로 노트를 읽고 씀  
> 역할 · 기능 정의, 권한 · 맥락 공유 규칙 설계, 테스트 · 운영 (코드는 Claude 보조)

Obsidian 볼트 안에서 여러 AI를 함께 쓰려고 만든 플러그인입니다.  
데스크톱 전용이고, 지금은 제 볼트에서만 쓰고 있습니다. (v0.48.0)

## 무엇을 하나

- AI 하나가 캐릭터 하나. 캐릭터마다 탭, 대화 기록, 성격 설정이 따로 있음
- 명령 하나로 모든 캐릭터를 나란히 열기
- 파티 전체 대화를 노트로 저장

연결할 수 있는 AI는 세 종류입니다.

| 종류 | 예 |
|---|---|
| 명령줄 도구 | Claude Code, Codex, Gemini CLI |
| 웹 API | OpenAI, Anthropic, Gemini, OpenRouter 등 OpenAI 호환 API |
| 로컬 모델 | Ollama, LM Studio |

## 설계에서 신경 쓴 것

### 맥락은 나누되, 섞지 않기

한 캐릭터에게 한 이야기를 다른 캐릭터가 모르면, 같은 설명을 여러 번 해야 합니다.  
그래서 메시지를 보낼 때, 그 캐릭터의 마지막 답변 이후 다른 탭에서 오간 대화를 요약해 앞에 붙입니다.

- 붙은 내용은 배경 정보로만 쓰고, 답은 자기에게 온 요청에만
- 공유는 캐릭터별로 켜고 끌 수 있음
- 길이 제한을 넘으면 오래된 내용부터 빠짐

예를 들어 한 캐릭터가 작업일지 구조를 정하면, 다른 캐릭터는 그 구조로 기록을 이어갈 수 있습니다.

### 권한은 AI가 아니라 플러그인이 지키기

AI마다 파일을 쓰는 방식과 권한 설정이 다릅니다.  
같은 볼트를 여러 AI가 만지면, 어디까지 허용했는지 AI별로 따로 기억해야 합니다.

그래서 권한을 캐릭터 단위로 다섯 단계로 나눴습니다.

| 단계 | 할 수 있는 일 |
|---|---|
| Read only | 읽기만. 바꿀 때마다 먼저 물어봄 |
| Edit chosen vault folders | 지정한 폴더 안에서만 수정 |
| Edit the whole vault | 볼트 전체 수정, 명령 실행은 불가 |
| Edit the vault + chosen outside folders | 볼트 전체와 지정한 바깥 폴더 |
| Full access | 제한 없음 |

여기에 옵션을 하나 더 뒀습니다.  
AI 자체의 파일 쓰기 기능을 끄고, 플러그인의 노트 도구로만 읽고 쓰게 하는 것입니다.  
도구는 목록 · 읽기 · 검색 · 쓰기 · 부분 수정 · 덧붙이기 · 이동 7가지이고, 모두 권한을 확인한 뒤 실행됩니다.  
이렇게 하면 어떤 AI를 연결해도 같은 기준이 적용됩니다.

권한 밖의 작업은 승인 창을 띄우고, 승인은 한 번만 유효합니다.

### 오래 켜 두는 도구라서

작업하는 동안 옆에 계속 띄워 두는 도구라, 보기에도 편해야 했습니다.

- 캐릭터별 색과 이미지(픽셀 아트 모드 포함), 팔레트 8종
- 노트를 쓰고 있으면 캐릭터가 취미 활동을 하고, 한동안 아무것도 안 하면 잠듦
- 움직임 효과는 끌 수 있음

## 쓰면서 알게 된 것

- 권한을 바꾼 뒤에도 접근이 안 되면, 대화를 새로 시작해야 반영되는 경우가 있었음
- Windows에서는 Codex가 편집 권한이 있어도 쓰기에 실패할 때가 있음
- 웹 API 키가 플러그인 설정 파일에 평문으로 저장됨 → 볼트를 git으로 관리한다면 그 파일을 제외해야 함

## 역할

어떤 기능이 필요한지, 맥락을 어디까지 공유할지, 권한을 어떻게 나눌지는 제가 정했습니다.  
코드는 Claude의 도움을 받아 작성했고, 실제 볼트에서 쓰면서 테스트하고 고쳤습니다.  
기능 안내 문서도 플러그인 코드를 기준으로 AI와 함께 정리해 볼트에 두었습니다.

> **Summary**  
> What · An Obsidian plugin that runs several AIs side by side as character tabs  
> Key call · Instead of relying on each AI's own file access, the plugin reads and writes notes under one permission rule  
> Role · Feature definition, permission and context-sharing rules, testing and daily use (code written with Claude's help)

I built this plugin to use several AIs together inside my Obsidian vault.  
It is desktop-only, and for now I am the only user. (v0.48.0)

## What it does

- One AI, one character. Each has its own tab, conversation history, and personality
- One command opens every character side by side
- The whole party's conversation can be saved as a note

It connects to three kinds of AI.

| Kind | Examples |
|---|---|
| Command-line tools | Claude Code, Codex, Gemini CLI |
| Web APIs | OpenAI, Anthropic, Gemini, OpenRouter, and other OpenAI-compatible APIs |
| Local models | Ollama, LM Studio |

## Design decisions

### Share context without mixing it up

If one character doesn't know what I told another, I end up explaining the same thing several times.  
So when I message a character, the plugin prepends what happened in the other tabs since that character last replied.

- The shared part is background only; the character answers just its own request
- Sharing can be turned on or off per character
- Past the length limit, the oldest content drops first

For example, one character can set up a work-log format, and another can keep logging in that format.

### Let the plugin enforce permissions, not each AI

Every AI handles file access and permissions differently.  
With several AIs touching one vault, I would have to remember what I allowed for each one.

So permissions are set per character, in five levels.

| Level | What it allows |
|---|---|
| Read only | Read only; asks before every change |
| Edit chosen vault folders | Edit inside chosen folders |
| Edit the whole vault | Edit anywhere in the vault, no commands |
| Edit the vault + chosen outside folders | The vault plus chosen outside folders |
| Full access | No limits |

On top of that, there is one more option.  
It turns off the AI's own file writing and routes all note access through the plugin's tools.  
There are seven tools (list, read, search, write, edit, append, move), and each checks permissions before it runs.  
That way, the same rule applies whichever AI is connected.

Anything outside the allowed scope opens an approval prompt, and an approval is good for one action only.

### Built to stay open all day

It sits next to my notes while I work, so it had to be pleasant to look at.

- Per-character colors and images (with a pixel-art mode), eight palettes
- Characters pick up a hobby while I write and fall asleep when I'm idle
- Motion effects can be turned off

## What I learned from using it

- After changing permissions, a character sometimes needed a new conversation before the change took effect
- On Windows, Codex sometimes fails to write even with edit permission
- Web API keys are stored in plain text in the plugin's settings file → if the vault is in git, that file must be excluded

## My role

I decided what features it needed, how much context to share, and how to split permissions.  
The code was written with Claude's help, and I tested and fixed it by using it in my own vault.  
I also wrote a feature guide in the vault with AI, based on the plugin code.
